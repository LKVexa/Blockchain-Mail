# Open the integrated workspace

Version 3.9.1-local.1. Mail, the local signed ledger, the puzzle workflow and the hardened blank console are in one portable Windows x64 package.

1. Extract the package into a new folder under `D:\Codex`. Preserve older packages and data.
2. Open `Start-Workspace.cmd` or `Start-Workspace.vbs` in the parent package folder. Startup displays file counts and stages, with Cancel. The supervisor freshly checks every launch file, each path for redirects, and the independent Node runtime pin before starting. No trusted verification cache is used.
3. Choose **Create new workspace** for a fresh vault. Save the generated four recovery words separately. For an existing protected vault, enter the original four words instead.
4. The console opens **Workspace mail** at **127.0.0.1**. Enter the same recovery words in the page to unlock its private API, then choose **Open mailbox**. First login assigns an available `rmail@127…` address from the signed local register. Choose **New message**, enter a local or Internet recipient, and press **Send**. Delivery follows the address automatically. Inbox and Sent show only this account’s messages.
5. Use the light/dark theme button. Closing the console stops its owned backend. **Lock workspace** clears the page by reloading it and asks for the recovery words again.

New game mailboxes use addresses such as **owner@127.0.0.2**. The signed ledger records each reservation and rejects reuse of an address or its host within this ledger. **Signed ledger → Local 127 address register** shows the reservations. The service reserves 127.0.0.1. Mailbox hosts are logical identities, and do not start extra network listeners. New allocation uses 127.0.0.2 through 127.0.0.254, with at most 253 claims. Existing signed mailbox addresses are preserved; a new local127 operation explicitly reconciles any earlier127 resources. Copied or restored vaults retain the authority and chain identity but can run as separate histories whose reservations are not coordinated. An external saved checkpoint is needed to detect a complete history rollback. This register does not establish global uniqueness across copies or inventory other Windows applications.

Saved state, signing and mailbox credentials, game registry objects, message/ledger rows, private API requests/responses, backups and default browser exports use independently authenticated outer encryption. The canonical signed ledger, message signatures and inner object codec are preserved. Browser exports have the `.workspace-export` extension: use the parent **Open-Private-Export.cmd** utility and the same recovery words to recover an explicit decrypted copy. Choose its original file extension, such as `.eml`, `.json` or `.bin`.

The package also includes **Protect-Package.cmd** and **Open-Protected-Package.cmd** to protect/recover an entire ZIP with an external recovery key. Recovery always writes a new file. No key is bundled or automatically saved with a vault or archive.

Use generated recovery words for new workspaces. The supplied JA21 recovery mapping is SHA-256 over its exact ordered word representation; arbitrary human-picked words do not gain password-hardening from that mapping. A lost key cannot be recovered.

Public interface files, clear index/size metadata, loopback socket addresses/timing, running memory and the active Windows/WebView browser profile remain outside this protection. This is one local operator vault; key holders can obtain its mailbox credentials. It is not recipient-held end-to-end encryption, a public consensus blockchain or an operating-system sandbox.

The inbound SMTP listener is disabled because its plain authentication protocol would bypass the protected pipeline. The shared protected compose form sends locally or directly through recipients’ Internet DNS MX servers. An envelope is a signed one-use send permit, not a transferable coin. Sudoku checking gates local issuance; it does not perform consensus mining or earn a mining reward.

The original JA21 4.3.3 launcher executable embeds a native 4.2.4 cipher engine and R12 tuple. Those exact pinned assets are recovered and included. **Protect-Native-Package.cmd** and **Open-Native-Package.cmd** use the actual native `.ja21pkg` ZIP codec, delivering the key through a private process-checked pipe. Use a fresh generated recovery key for each new native archive; preserve the original key for recovery. Live storage and API frames retain the independent authenticated protection described above. The supplied native engine describes AES-256-GCM as its confidentiality boundary and its 5D provenance as experimental. The cipher engine source is not supplied.

The fully defined 8Sphere formulas are implemented in the standalone `protection/math/eight-sphere-math.mjs` reference module. Open `reference/eight-sphere-math-report.html` for the implementation and missing-definition record. Its 31 focused tests and 14 independent checks passed. The complete numerical functions, coefficients, classifier, score model, solver profile and reversible mapping are not supplied, so changing the native cipher to the complete master law remains incomplete. The reference module is not used as encryption.

The release report records code-level native WebView2 end-to-end testing of wrong-key refusal, unlock, both themes, connection, all three board checks, signed local127 allocation, message preparation, send, Inbox, receipt replay, saved ledger verification and lock/reload. The actual PowerShell console compile and supervisor startup also passed a read-only code observer test. No Computer Use was used. Interactive archive file/key dialog acceptance remains unperformed. The Desktop quarantine is unchanged.

Console 1.0.2 is a documented derivative. It uses the standard WebView2 display host, adds visible loading/failure/retry states, requires the working live interface and verifies page readiness. Its provenance record identifies changes from original console 1.0.1. The previous published package and Desktop quarantine remain unchanged. Current status is recorded in `PROTECTION_STATUS.json` and `RELEASE_VERIFICATION.json`.

The launcher requires Windows x64, Windows PowerShell 5.x and an installed Microsoft Edge WebView2 runtime. It uses the supplied Node runtime and sealed console SDK; it does not download dependencies. Its default local port is 8787 and can be changed in the opening dialog. An occupied port fails without stopping an existing process.

Older plaintext state cannot be silently converted in place: startup refuses it rather than leave old plaintext SQLite/WAL pages behind. Preserve the old application and data; this release starts a fresh protected vault or restores an encrypted backup into a new directory. An exact audited plaintext-to-protected migration remains a separate operation.

Read-only startup verification, including bootstrap, measured 50.91 seconds for the previous 7,846-file package and 18.87 seconds for the interim 7,847-file update in this environment. The final 7,854-file production launch measured 12.87 seconds for verification. Runs used different Windows tokens and loads, so these are observations, not a benchmark guarantee. Every inventory file and its ancestors are still checked afresh. Recovery input, protected backend initialization and console compilation add to total startup time. The startup smoke bypassed only the recovery prompt with public synthetic words; interactive recovery-dialog acceptance was not performed.
